1. Processor Modes & General-Purpose Registers ١. أوضاع المعالج والمسجلات العامة (Registers)

Modern x86-64 processors boot in 16-bit Real Mode for legacy compatibility, transition through 32-bit Protected Mode, and execute 64-bit applications in 64-bit Long Mode. In Long Mode, the CPU provides sixteen 64-bit general-purpose registers (GPRs), an instruction pointer (RIP), and status flags (RFLAGS).

32-bit Zero-Extension Rule: Writing to a 32-bit sub-register (such as EAX) automatically zeroes the upper 32 bits of RAX. Writing to 16-bit (AX) or 8-bit (AL/AH) preserves the upper bits.

تبدأ معالجات x86-64 الحديثة العمل في الوضع الحقيقي (Real Mode - 16-bit) للتوافق الرجعي، ثم تنتقل عبر الوضع المحمي (Protected Mode - 32-bit)، وتُنفّذ البرامج الحديثة في الوضع الطويل (64-bit Long Mode). يوفر المعالج في هذا الوضع ستة عشر مسجلاً عاماً (GPRs) بحجم 64 بت، ومؤشر التعليمات (RIP)، ومسجل الأعلام (RFLAGS).

قاعدة التصفير العلوي (Zero-Extension): الكتابة في مسجل فرعي بحجم 32 بت مثل EAX تقوم تلقائياً بتصفير البتات الـ 32 العليا من RAX، بينما الكتابة في 16 بت (AX) أو 8 بت (AL) تُبقي البتات العليا دون تغيير.

2. Memory Addressing, Assembler Syntax & Machine Encoding ٢. عنونة الذاكرة وصيغ المجمّعات والترميز الثنائي

x86-64 uses little-endian byte ordering (least significant byte at the lowest memory address) and supports scaled-index-base addressing: [base + index * scale + displacement], where scale is 1, 2, 4, or 8. Use MOV to transfer data and LEA (Load Effective Address) to compute memory addresses without dereferencing memory.

At the machine-code level, instructions consist of optional legacy prefixes, a REX prefix (0x40–0x4F enabling 64-bit operand size REX.W and registers R8–R15), a 1-to-3 byte opcode, a ModR/M byte, an optional SIB byte, and displacement/immediate fields.

تعتمد معمارية x86-64 ترتيب البايتات الصغير أولاً (Little-Endian) حيث يُخزَّن البايت الأقل أهمية في العنوان الأصغر، وتدعم صيغة العنونة المركّبة: [base + index * scale + displacement] حيث تأخذ scale القيم 1 أو 2 أو 4 أو 8. نستخدم تعليمة MOV لنقل البيانات، وتعليمة LEA لحساب العناوين الفعالة دون الوصول للذاكرة.

على مستوى لغة الآلة، تتكون التعليمة من بادئات اختيارية، وبادئة REX (من 0x40 إلى 0x4F لتفعيل حجم 64 بت والمسجلات الإضافية R8–R15)، ثم كود العملية (Opcode)، وبايت ModR/M، وبايت SIB اختياري.

          3. Arithmetic, Status Flags & Control Flow
          ٣. العمليات الحسابية والأعلام وتدفق التحكم
        


        

          

            

              Arithmetic and logical instructions update bits inside RFLAGS: Zero Flag (ZF), Sign Flag (SF), Carry Flag (CF for unsigned overflow), and Overflow Flag (OF for signed overflow).
              CMP a, b computes a - b without storing the result, whereas TEST a, b computes bitwise a & b—making test rax, rax the idiomatic zero check.
            

          

          

            

              تُحدّث العمليات الحسابية والمنطقية بتات مسجل الحالة RFLAGS: علم الصفر (ZF)، وعلم الإشارة (SF)، وعلم الحمل (CF للفيض غير الموقّع)، وعلم الفيض (OF للفيض الموقّع).
              تحسب CMP a, b ناتج a - b دون حفظه، بينما تحسب TEST a, b عملية a & b، لذا تُعد test rax, rax الطريقة القياسية لفحص الصفر.

          4. Stack Frames & Dual x86-64 ABIs (System V vs. Microsoft x64)
          ٤. إطارات المكدس ومواصفات ABI (نظام Linux/Unix مقابل Windows)
        


        

          

            

              The hardware stack grows downward toward lower addresses via RSP. Both major 64-bit ABIs require
              16-byte stack alignment immediately prior to executing a CALL instruction (so RSP ends in 0x...8 on function entry after the 8-byte return address is pushed).
            

          

          

            

              ينمو المكدس (Stack) نحو العناوين الأقل عبر المؤشر RSP. تشترط كلتا الواجهتين الثنائيتين (ABIs)
              محاذاة المكدس على حدود 16 بايت قبل تنفيذ تعليمة CALL مباشرةً (بحيث يكون عنوان RSP عند دخول الدالة منتهياً بـ 8 بعد دفع عنوان العودة ذي الـ 8 بايت).

          5. Linux System Calls & GCC Extended Inline Assembly
          ٥. نداءات نظام لينكس والتجميع المضمّن في GCC
        


        

          

            

              On x86-64 Linux, user-space programs invoke the kernel via the SYSCALL instruction. Place the syscall number in
              RAX and pass up to six arguments in RDI, RSI, RDX, R10, R8, and R9 (note R10 replaces RCX because SYSCALL clobbers RCX and R11).
            

          

          

            

              في نظام لينكس على معمارية x86-64، تستدعي برامج المستخدم النواة عبر تعليمة SYSCALL. نضع رقم نداء النظام في
              RAX ونمرر المعاملات بالترتيب في RDI، RSI، RDX، R10، R8، وR9 (لاحظ استخدام R10 بدلاً من RCX لأن التعليمة تستخدم RCX وR11 داخلياً).

          6. SIMD Vectorization & Microarchitectural Performance
          ٦. المعالجة المتجهية SIMD وتحسين الأداء المعماري الدقيق
        


        

          

            

              Data-level parallelism on x86-64 scales across 128-bit XMM0–XMM15 (SSE), 256-bit YMM0–YMM15 (AVX/AVX2), and 512-bit ZMM0–ZMM31 (AVX-512) vector registers.
              When tuning hot loops, measure latency (cycles from input ready to output ready), reciprocal throughput (cycles per instruction issue), and execution port contention using empirical databases like uops.info and Agner Fog's instruction tables.
            

          

          

            

              يتوسع التوازي على مستوى البيانات في x86-64 عبر مسجلات المتجهات: XMM0–XMM15 بحجم 128 بت (SSE)، وYMM0–YMM15 بحجم 256 بت (AVX/AVX2)، وZMM0–ZMM31 بحجم 512 بت (AVX-512).
              لتحسين الحلقات الحرجة، يجب قياس زمن التأخير (Latency)، والإنتاجية العكسية (Reciprocal Throughput)، وتوزيع منافذ التنفيذ (Execution Ports) بالاعتماد على قواعد بيانات مثل uops.info وجداول Agner Fog.

          7. Bare-Metal Long Mode Transition & Debugging / RE Workflow
          ٧. الانتقال للوضع الطويل 64-بت ومنهجية التنقيح والهندسة العكسية
        


        

          

            
Escalating to 64-bit Long Mode

            
    
              
  1. Verify extended CPUID support and execute CPUID with EAX = 0x80000001 to confirm bit 29 of EDX (Long Mode) is set.
    2. 
              
  2. Build an identity-mapped 4-level page table hierarchy (PML4 → PDPT → PD → PT) and load the physical address of PML4 into CR3.
    3. 
              
  3. Enable Physical Address Extension (CR4.PAE = 1), set the Long Mode Enable bit in the IA32_EFER MSR (0xC0000080, bit 8), and enable paging (CR0.PG = 1).
    4. 
              
  4. Load a 64-bit Global Descriptor Table (LGDT) with a 64-bit code segment descriptor (L = 1, D = 0) and execute a far jump into 64-bit code.
    5. 
            

            
Practical Linux Inspection & Debugging Commands

            

              Inspect ELF headers with readelf -hS binary, disassemble with Intel syntax via objdump -d -M intel binary, trace kernel syscalls via strace ./binary, and step through registers/stack frames using gdb with pwndbg or GEF.
            

          

          

            
خطوات الانتقال إلى الوضع الطويل 64-بت (Long Mode)

            
    
              
  1. التحقق من دعم CPUID الموسّع وتنفيذ CPUID بالقيمة EAX = 0x80000001 للتأكد من تفعيل البت 29 في EDX.
    2. 
              
  2. بناء جداول الصفحات رباعية المستويات (PML4 ← PDPT ← PD ← PT) وتحميل العنوان الفيزيائي لـ PML4 في المسجل CR3.
    3. 
              
  3. تفعيل توسعة العناوين الفيزيائية (CR4.PAE = 1)، وتفعيل بت الوضع الطويل في مسجل IA32_EFER (0xC0000080، البت 8)، ثم تفعيل التصفح (CR0.PG = 1).
    4. 
              
  4. تحميل جدول الواصفات العام (LGDT) مع واصف مقطع كود 64-بت (L = 1, D = 0) والقفز البعيد إلى كود 64-بت.
    5. 
            

            
أوامر الفحص والتنقيح العملية على لينكس

            

              افحص ترويسات ELF عبر readelf -hS binary، وفكّك التعليمات بصيغة Intel عبر objdump -d -M intel binary، وتتبّع نداءات النظام عبر strace ./binary، ونقّح المكدس والمسجلات باستخدام gdb مع pwndbg أو GEF.
